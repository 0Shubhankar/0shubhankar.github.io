# Housing Policy Engine — 1.0 prototype
Standalone ES module for Project 19, Gotham. No external dependencies; Node 18+ and modern browsers. Original HTML, CSS and artwork are not included or modified.

## Run
`npm test` in this folder. `node demo.js` writes a scenario comparison to stdout. Serve the website over HTTP for browser ES module imports.

## Integration
Copy this engine folder into portfolio/19/ (back up the older engine first). Create a separate copy of the original HTML for preview. In a module script import `createEngine` from `./engine/housing-engine.js`. Instantiate once per game; map existing buttons to policy IDs and zones, call `applyPolicy(id, zone, amount)` and `advance()` only at the chosen simulation-period boundary. Use `indicators()` to populate existing narrative placeholders and optional metrics. `reset()` restarts; `history()` returns a JSON-serializable event log. Do not advance on every click by default. Game pacing and scene mapping remain to be verified in the original source. No automatic deployment.

```js
import {createEngine} from './engine/housing-engine.js';
const game = createEngine();
game.applyPolicy('density','inner',0.25);
const results = game.advance();
console.log(results.zones, game.history());
```

## Policy IDs and units
- density: fractional increase in permitted total units (0–1)
- rentControl: cap on annual market-rent growth (0–0.2)
- inclusionary: affordable share of new private construction (0–0.5)
- peripheralHousing: integer publicly financed affordable units, in selected zone
- shelters: integer emergency household places; not permanent housing
- supportiveHousing: integer affordable units with ongoing support, delivered after one period
- developerIncentives: fractional construction-cost subsidy proxy (0–0.5), one period
- communityInvestment: USD expenditure; reduces illustrative homelessness risk
- none: no intervention
Zone IDs: centre, inner, suburban, periphery. All policies accept defaults if amount omitted. Invalid choices throw without committing the policy.

## Model and assumptions
Fictional four-zone rental market, five fixed income cohorts. One model period represents one year; the game does not need to adopt a fixed number of years. Households grow at 1.2% by cohort; incomes grow 2.5%; population increases by approximately 2.5 persons per new household. Construction completes after one period, market demolitions occur at 0.2% annually. Rent growth = clamp(1.6 × (households/stock − 0.95), −0.15, 0.15), subject to regulation. Affordable units are allocated lowest-income first; market units highest-income first, with a 50% income affordability ceiling in either tenure. Affordable rent assumed $500/month. Developer construction is proportional to existing market units, constrained by permitted stock, and adjusted by a gross rental-yield proxy, inclusionary share and incentives. Housing insecurity is the remaining households after allocation; homelessness is a heuristic based on prior homelessness, unmet need, rent-pressure displacement proxy and supportive housing. Shelter places reduce unsheltered need, not total homelessness. The policy budget is a fixed illustrative $120m, not a municipal revenue model. Capital and service costs are charged as documented in code; if recurring services cannot be funded, the model removes their service capacity. These are modeling choices, not empirical estimates. No external data or calibrated causal coefficients.

## Limitations
Allocation is repeated each period; no individual household tracking, tenure security, migration between zones, owner-occupancy, land-price dynamics, or explicit developer cash-flow optimization. Displacement is a proxy, not observed evictions or moves. Supportive housing allocation is simplified and does not track individual beneficiaries. Rent control affects the zone-wide market rent rather than a regulated submarket. Shelter places represent household equivalents, not persons. The initial occupancy is an illustrative aggregate, not generated by the affordability allocation, so the first period can show a discontinuity. Tests establish software invariants, not scientific validity. Before research use, calibrate parameters, replace unsupported mechanisms where needed, and validate against evidence. Before publication, verify original game branches and browser integration.

## HPE 1.1 / Gotham preview
- The private zoning capacity baseline is now 104% of initial stock (illustrative). Public housing projects include dedicated site approval if needed. Density can therefore relax a binding private construction limit.
- Existing occupancy persists; only 2.5% of the gap between existing occupancy and affordability-screened target is lost per period, and new placements are gradual. Homelessness is a flow: new insecure households face an illustrative risk, existing homelessness has a 12% annual exit rate, and newly completed supportive units can provide additional exits. These are not estimated coefficients. No household-level tenure tracking or validated causal claims are implied.
- The game retains the three original policy stages and choice labels, uses two simulation periods per stage, and replaces scripted failure/success with numeric reviews. Some choices are recorded without a quantified effect; proxy choices are labeled. The original page is not modified. The preview copies its CSS, adds a small housing indicator line, and uses a rewritten narrative.
- Run `npm test` (23 tests including 96 complete game paths), `node demo.js`, and serve the project via HTTP to view `housing-policy-preview.html`. Browser visual verification is still required.
